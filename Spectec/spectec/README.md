# SpecTec Enrichment Pipeline

This repository contains the SpecTec-based enrichment step shared by the three WebAssembly evaluation pipelines:

* WasMixer evaluation;
* wasm-mutate evaluation;
* SWAMPED evaluation.

SpecTec is used to evaluate formal validity and semantic equivalence between original binaries and their corresponding transformed versions.

The enrichment step operates on existing experiment results. It does **not** execute additional obfuscation or mutation steps. Instead, it reads an existing metrics CSV, reconstructs the corresponding binary pairs, runs SpecTec analyses, and produces an enriched CSV containing formal and semantic validation results.

---

# Directory structure

```text id="9m8z3f"
spectec_pipeline/
├── wasm_runtime.py                  # Runtime helpers and export inspection
├── spectec_common.py                # Shared SpecTec logic, equivalence checks, CSV handling
├── spectec_analysis_wasmixer.py     # SpecTec enrichment for WasMixer results
├── spectec_analysis_wasmmutate.py   # SpecTec enrichment for wasm-mutate results
└── spectec_analysis_swamped.py      # SpecTec enrichment for SWAMPED results
```

The three analysis scripts are lightweight command-line wrappers around:

```text id="wzq9a1"
spectec_common.py
```

All evaluation pipelines use the same output directory structure:

```text id="7k9x1r"
<outdir>/<sample>/<sample>__<mutant_id>/*.wasm
```

Therefore, the same path reconstruction mechanism is used for WasMixer, wasm-mutate, and SWAMPED without tool-specific handling.

---

# Requirements

git clone https://github.com/Wasm-DSL/spectec.git

The enrichment pipeline requires:

* A compiled SpecTec reference interpreter binary.

* WABT tools:

  * `wasm2wat`

  available through `PATH` or specified using `--wabt-bin`.

* Existing experiment results:

  * metrics CSV generated by:

    * `run_wasmixer.py`;
    * `run_wasmmutate.py`;
    * `run_swamped.py`.
  * corresponding output directory containing generated binaries.

The original CSV and generated binaries must remain available during enrichment.

# Enrichment process

For each row of the input CSV, the pipeline performs the following steps.

## 1. Recover original binary path

The original file path is reconstructed using:

```text id="a3j8lf"
--dataset / relpath_orig
```

`relpath_orig` is stored as a relative path in the experiment CSV.

Therefore, the `--dataset` argument must be exactly the same directory used during the original experiment.

If a different dataset path is provided, the original file cannot be located.

---

## 2. Recover transformed binary path

The transformed file is reconstructed using:

```text id="xv8s1d"
--obf-dir/<sample>/<sample>__<mutant_id>/*.wasm
```

The lookup relies on:

* `sample`;
* `mutant_id`.

Each experiment directory contains a single `.wasm` file. Other files (`.log`, `.json`, `.wast`) are ignored.

---

## 3. Formal validity checking

SpecTec is executed independently on:

* the original module;
* the transformed module.

Command:

```text id="6f0o0v"
spectec_bin <file.wasm>
```

The result is interpreted as:

* exit code `0`:

  * module accepted by the formal specification;

* non-zero exit code:

  * module rejected.

The following columns are generated:

```text id="a1c2q8"
spec_valid_orig
spec_valid_obf
```

---

## 4. Semantic equivalence checking

Semantic equivalence is evaluated by executing both modules with SpecTec.

The pipeline first identifies the entry point using the following priority:

1. `_start`
2. `main`
3. first exported function

For the selected function:

* five predefined input vectors are generated for each parameter type;
* the function is invoked on the original module;
* the function is invoked on the transformed module;
* outputs are compared.

The result is reported as:

| Result     | Meaning                                   |
| ---------- | ----------------------------------------- |
| `yes`      | all executions produced identical outputs |
| `partial`  | some executions matched                   |
| `no`       | no execution matched                      |
| `skipped`  | semantic check could not be performed     |
| `no_entry` | no suitable exported function found       |
| `err`      | execution error occurred                  |

---

## 5. Writing enriched results

The output CSV contains all original columns plus:

```text id="1j7x8p"
spec_valid_orig
spec_valid_obf

semantic_equivalence_bool

spec_errors_orig
spec_errors_obf

spec_violation_count

interpreter_crash
```

The enrichment process is resumable.

Rows already present in the output CSV are detected using:

```text id="8x4m3q"
(relpath_orig, mutant_id)
```

and skipped automatically.

Therefore, interrupted executions can safely be restarted.

# Usage

The three drivers share the same command-line interface.

Example for WasMixer:

```bash id="j1f9sf"
python3 spectec_analysis_wasmixer.py \
    --dataset <dataset_used_for_original_run> \
    --input-csv <metrics_csv> \
    --output-csv <enriched_csv> \
    --obf-dir <output_directory_used_for_original_run> \
    --spectec-bin <spectec_binary> \
    --wabt-bin <WABT_directory> \
    --timeout 120 \
    --n-inputs 5 \
    --cores <number_of_workers> \
    --batch-size 50
```

For the other pipelines:

```bash id="qx3x3s"
python3 spectec_analysis_wasmmutate.py
```

or:

```bash id="b3x7kf"
python3 spectec_analysis_swamped.py
```

All options keep the same meaning.

Only the input CSV and output directory must correspond to the selected evaluation pipeline.

---

# Parameters

## Timeout

```text id="h4m7mq"
--timeout
```

Maximum execution time for one SpecTec invocation.

Default:

```text id="h3j5aw"
3600 seconds
```

---

## Semantic inputs

```text id="2p6v0r"
--n-inputs
```

Number of input vectors tested during semantic equivalence checking.

Default:

```text id="y7v8hx"
5
```

---

## Batch flushing

```text id="8t3z6m"
--batch-size
```

Number of processed rows buffered before writing results to disk.

Default:

```text id="3m8q2h"
50
```
